# Windows 実機 通しテスト手順書（段階13）

本番の大会で使う予定の Windows PC で、検証用画面を使って模擬レースを通しで行い、
自動テスト（Linux 上の Node）では確認できないことを確かめるための手順です。
**ここに書いた項目は、実施して結果を報告いただくまで「未確認」として扱います。**

> ### ⚠ 強制停止は「開始した時点」で登録してください
> 強制停止（全車停止）は、**停止が始まったその時点で**検証用画面の「強制停止」に登録してください（終了未定のまま登録し、再開時に終了日時を入力します）。
> 登録が遅れると、停止中は全チームのラップが伸びたように計算され、**全チームに「ペース低下」の警告が出ます**（アプリの不具合ではなく、入力のタイミングによるものです。自動通しテストでも、未登録の停止で同じ警告が出ることを確認しています）。
> 後から過去の停止として登録すると、ラップの除外と予測は正しく再計算されますが、それまでに出た警告の記録は残りません。

## 0. 準備

### 0-1. 対象のコード
- ブランチ `claude/wgc-race-management-system-j8o71p` の最新コミット（`git log -1 --oneline` の結果を記録シートに書く）
- 構成：Electron 33.4.11 / better-sqlite3 12.11.1（`docs/dev-setup.md` の手順でセットアップ済みであること）
- S モードではない Windows であること

### 0-2. 既存のデータを退避する（**本番データに影響させないため必須**）
アプリには DB の保存場所を切り替える設定がないため、テストは通常と同じ `%APPDATA%\wgc-race-manager\` に保存されます。
1. アプリをすべて終了する
2. エクスプローラーのアドレス欄に `%APPDATA%` と入力して開く
3. `wgc-race-manager` フォルダがあれば、名前を `wgc-race-manager.backup-YYYYMMDD` に変更する（**削除しない**）
4. テスト後の戻し方は「6. 後片付け」を参照

### 0-3. 用意するもの
- 基準の時計（スマートフォンのストップウォッチと、秒まで表示される時計）
- この手順書の「記録シート」（印刷または Excel）
- 電源設定の確認には **管理者として実行** したコマンドプロンプト（`powercfg` 用。Windows のセキュリティ設定は変更しません）

### 0-4. 起動
```
cd C:\dev\wgc\wgc-race-manager
npm.cmd run build
npm.cmd run start
```
起動・DB 確認欄で `dbSchemaVersion` = 5、`dbIntegrity` = ok、DB のパスが `%APPDATA%\wgc-race-manager\wgc-race-manager.sqlite` であることを記録する。

## 1. 短縮版（60〜90 分）

まずこちらを行い、問題がなければ「2. 長時間版」に進んでください。時刻は START からの経過時間です。

| 時刻 | 操作 | 確認すること |
|---|---|---|
| 準備 | 大会を作成（終了予定 = 開始予定 + 75 分）。自チーム + 他チーム 5 チーム程度。操作者を 2 名登録し 1 名を選択 | 作成できる |
| 0:00 | START（**同時に基準のストップウォッチを開始**） | 経過時間が進む。`powercfg /requests` に DISPLAY・SYSTEM の要求がある |
| 0:00〜 | 自チーム・他チームの通過を、実際のレースに近い間隔（例：各チーム 2〜5 分ごと）で登録し続ける | 周回数・ラップタイム・暫定順位が更新される |
| 0:10 | 車両データを 2〜3 周分入力（空欄・`062.50` を含める）、メモを 1 件 | 入力値がそのまま表示される |
| 0:15 | 操作者を切り替える | 時計が止まらない |
| 0:20 | PAUSE → 2 分後に RESUME | PAUSE 中も残り時間は減り続け、経過時間は止まる |
| 0:25 | 誤った通過記録を 1 件登録 → 削除。別の記録の通過日時を修正。UNDO を 1 回 | 周回番号・ラップタイム・順位が再計算される |
| 0:30 | **強制停止が始まったとして、その場で登録（終了未定）** → 5 分後に終了日時を入力 | 停止中は全チームの「ペース低下」が出ない。停止と重なったラップが除外される |
| 0:40 | 基準のストップウォッチとアプリの経過時間を比べて記録（PAUSE の 2 分を差し引く） | 差を記録する |
| 0:45 | **タスクマネージャーで強制終了** → 1〜2 分待って再起動 | 「前回は正常に終了しませんでした」と復旧確認待ちが表示される。経過時間は停止中も含めて進んでいる。確認前は登録がエラー、メモは可能。確認後は通常どおり |
| 0:50 | × ボタンで閉じる（確認ダイアログで「終了する」）→ 再起動 | 「前回の終了：正常終了」。復旧確認待ちにならない。操作者は「未設定」に戻る |
| 0:55 | 警告一覧を見る。1 件を「確認済み」にする | 重要度順に表示。確認済みで一覧から消える |
| 1:00 | 過去の通過記録を追加（登録し忘れの想定） | 途中に入り、以降の周回番号が再計算される |
| 1:15 | END | 実況の登録がエラー。過去記録の操作はできる。`powercfg /requests` から要求が消える |
| 終了後 | CSV を出力し、Excel で 5 ファイルを開く | 文字化けしない。件数が記録シートと一致する |

## 2. 長時間版（2〜3 時間）

短縮版と同じ操作に加えて、以下を行います（終了予定 = 開始予定 + 3 時間程度）。

- 10 チーム（自チーム含む）で、合計 300〜500 件程度の通過を登録する（2 名で分担可）
- 強制停止を 2 回（1 回は **開始時点で登録**、1 回は終了時刻を後から修正）
- 1 時間ごとに、基準の時計とアプリの経過時間の差を記録する
- 途中でスリープ（または休止）→ 数分後に復帰し、「PC実日時 − マスタークロック」「復帰時の時刻ずれ」の値を記録する
- 途中で Windows の時刻を手動で 1 時間ずらし、10 分後に戻す（経過時間・記録が影響を受けないこと。「PC実日時 − マスタークロック」だけが変わること）。**自動時刻同期を一時的に切る必要がある場合は、テスト後に必ず元に戻す**
- 終盤（記録が多い状態）で、登録・画面更新に体感で遅れがないかを記録する
- チームを 1 つ削除し、記録とともに順位に「削除済み」で残ることを確認、その後復元

## 3. 段階12から持ち越している未確認の項目

| 項目 | 手順 | 記録すること |
|---|---|---|
| 強制電源断（段階12 項目 8） | 走行中に電源ボタン長押しで電源を切る → 再起動 | 起動が止まらない（整合性 ok）、確定済みの記録が残る、復旧確認待ちになる |
| ノート PC のフタを閉じる（段階12 項目 10） | 走行中にフタを閉じる → 数分後に開く | 何が起きたか（スリープしたか、画面が消えただけか）、復帰後の警告。アプリでは防げないため、運用上の注意として記録する |
| `powercfg /requests` の出力 | START 後に管理者のコマンドプロンプトで実行 | 出力をそのまま貼り付ける |
| スリープ復帰時の数値 | 2 章のスリープ確認 | 「PC実日時 − マスタークロック」「復帰時の時刻ずれ」の値（単調時計がスリープ中に止まるかの判断材料） |
| シャットダウン時の動作 | アプリを開いたまま Windows をシャットダウン | シャットダウンが止まらないこと、次回起動で「正常終了」と表示されること（Electron 33 では事前通知がないため再確認） |

## 4. 性能の記録（任意・合否判定なし）

アプリ自体には所要時間を表示する機能がないため、同じ PC で自動テストの性能測定を実行して数値を記録します（Node での計測で、Electron 内とは完全には一致しません）。

```
npm.cmd test -- tests/integration/performance.test.ts --silent=false
```

出力される「戦略計算」「警告判定」「記録登録」の平均・最大・p95 を記録シートに転記してください。目安は 50 ms ですが、**数値だけで合否は決めません**。アプリ操作時の体感（ボタンを押してから表示が変わるまでの遅れ）とあわせて判断します。

## 5. 回収するもの

1. 記録シート（下記）
2. CSV 出力フォルダ一式（5 ファイル）
3. DB のコピー：**アプリを終了してから** `%APPDATA%\wgc-race-manager\` のフォルダごとコピー（`-wal`・`-shm` ファイルがあれば一緒に）
4. 異常があった場合は画面のスクリーンショットと、その時刻

## 6. 後片付け

1. アプリを終了する
2. テストで使った `%APPDATA%\wgc-race-manager` を `wgc-race-manager.test-YYYYMMDD` に名前変更して残す（回収後に不要なら削除してよい）
3. 0-2 で退避したフォルダがあれば、名前を `wgc-race-manager` に戻す
4. 変更した Windows の時刻・電源（消灯時間など）の設定を元に戻す

---

## 判定の考え方

合否は記録シートをもとに確認して決めます（自動判定はしません）。次のいずれかがあれば不具合として報告してください。

- アプリが異常終了した、起動できなくなった、操作がエラーになるべきでない場面でエラーになった
- 確定した記録が消えた・変わった（CSV と記録シートの件数・時刻が合わない）
- 経過時間が基準の時計から PAUSE・停止では説明できないほどずれた（ずれの値を記録）
- 強制停止を開始時点で登録したのに、停止中に全チームのペース低下警告が出た
- 正常終了なのに「正常に終了しませんでした」と出た、またはその逆
