# 開発環境セットアップ（Windows）

## 必要なもの

- Windows 10 / 11（x64）
- Node.js **22.12 以上**（LTS 推奨）

C++ ビルドツール（Visual Studio Build Tools / Python）は**不要**です。
better-sqlite3 は配布元のビルド済みバイナリをダウンロードして使います（自動テスト用＝Node 用と、アプリ用＝Electron 33 用の 2 種類。D-073）。

**Windows の S モードでは起動できません。** S モードは Microsoft Store のアプリ以外の実行を禁止するため、`electron.exe` と SQLite のバイナリがブロックされます（「アプリケーション制御ポリシーによってこのファイルがブロックされました」）。「設定」→「システム」→「バージョン情報」のエディションに「S モード」と出る PC は使えません（解除は一方通行）。組織が管理する PC でも、アプリケーション制御で同様にブロックされることがあります。

## コードの取得（既存の AI Challenge 環境を壊さない方法）

既存のクローン（AI Challenge 用）の作業ブランチはそのままにして、WGC 専用のフォルダを `git worktree` で作ります。

```powershell
cd C:\dev\aichallenge-racingkart          # 既存クローン（例）
git status                                 # 現在のブランチと未コミットの変更を確認（worktree は既存の作業に影響しません）
git fetch origin claude/wgc-race-management-system-j8o71p
git worktree add -b claude/wgc-race-management-system-j8o71p C:\dev\wgc origin/claude/wgc-race-management-system-j8o71p
# 既に同名のローカルブランチがある場合：git worktree add C:\dev\wgc claude/wgc-race-management-system-j8o71p
#   → git -C C:\dev\wgc pull --ff-only
# そのブランチが既存クローン側で checkout 中の場合は worktree を作れません（既存側のブランチを勝手に切り替えないこと）
```

別フォルダへの新規クローンでも構いません：
`git clone -b claude/wgc-race-management-system-j8o71p --single-branch https://github.com/M4rim0/aichallenge-racingkart C:\dev\wgc`

- フォルダは OneDrive 等の同期フォルダの外、短いパス（例：`C:\dev\wgc`）に置いてください。

## 初回セットアップ

```powershell
cd wgc-race-manager
npm ci
```

`npm ci` は `package-lock.json` に固定されたバージョンをそのまま入れます（Windows 用のネイティブ部品も lockfile に含まれています）。

- `npm ci` の中で、**Electron 本体（約 100MB）と Electron 用の SQLite バイナリが自動でダウンロードされます**（`[wgc] 導入しました: …native\electron-v130-win32-x64\better_sqlite3.node` と表示されれば成功）。失敗した場合は、ネット接続を確認して `npm run setup:native`（SQLite）を実行してください。
- PowerShell で「スクリプトの実行が無効」と出る場合は `npm.cmd ci` / `npm.cmd test` / `npm.cmd run dev` のように `npm.cmd` を使うか、コマンドプロンプトで実行してください。
- 環境変数・設定ファイルは不要です。アプリ本体はオフラインで動作します。

## コマンド

| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発モードで起動（ホットリロードあり） |
| `npm run build` | `out/` にビルド |
| `npm start` | ビルド済みのアプリを起動 |
| `npm test` | 自動テスト（Vitest） |
| `npm run test:random` | 追加のランダム操作テスト（複数シード × 各 5,000 操作、10 分程度）。`WGC_RANDOM_SEEDS` / `WGC_RANDOM_OPS` で変更可 |
| `npm test -- tests/integration/performance.test.ts --silent=false` | 性能の記録（平均・最大・p95 を表示、合否判定なし） |
| `npm run typecheck` | 型チェック |

3. もう一度 `npm start` を実行しても 2 つ目のウィンドウが開かず、既存ウィンドウが前面に出ること（二重起動防止）

## 段階2の動作確認（手動）

1. `npm run build` → `npm start`
2. 検証用画面の「起動・DB確認」に `dbPath`（`%APPDATA%\wgc-race-manager\wgc-race-manager.sqlite`）、`dbSchemaVersion` = 5（段階12時点）、`dbIntegrity` = ok が表示されること
3. アプリを終了・再起動しても同じ表示になること

## 段階3の動作確認（手動・検証用画面）

1. 大会を作成する（終了予定を開始予定より前にするとエラーになること）
2. 大会を選択し、チームを追加する。自チームを2つ登録しようとするとエラーになること
3. チームを削除すると関連記録の件数が表示され、確認後に「削除済み」と表示されること
4. 「復元」で元に戻ること
5. アプリを再起動しても大会・チームが残っていること

※ 検証用画面の日時入力は PC のローカル時刻として扱います（正式 UI の入力方式は未決定）。

## 段階4の動作確認（手動・検証用画面）

1. 大会を選択し START → 経過時間が進むこと
2. PAUSE → 経過時間が止まり、残り時間は減り続けること。RESUME で再開すること
3. 走行中にアプリを終了して再起動 → 大会を選ぶと状態が RUNNING のまま、停止していた時間も含めて経過時間が復元されること（PAUSE 中に終了した場合は PAUSED のまま）
4. **Windows の時刻設定を手動で変更** → 起動中の経過時間・マスタークロックが影響を受けないこと（「PC実日時 − マスタークロック」の値だけが変わる）
5. 時刻を過去に戻した状態でアプリを起動 → 警告ダイアログと画面上の警告が出ること（記録は書き換わらないこと）
6. 実際の開始時刻の修正 → 経過時間が修正後の値で再計算されること。END 後も修正できること
7. END 後は START/PAUSE/RESUME/END がすべてエラーになること

## 段階5の動作確認（手動・検証用画面）

1. START 前の LAP REGISTER がエラーになること。START 後・PAUSE 中は登録でき、ラップタイムに一時停止中の時間が含まれること
2. END 後の LAP REGISTER がエラーになり、過去記録の追加はできること
3. 過去記録を途中に追加すると周回番号・ラップタイムが再計算されること。開始時刻以前・未来・同一日時はエラーになること
4. 通過日時の修正で、前後の記録を飛び越える修正がエラーになること
5. UNDO で直前の記録操作から順に取り消せること（START/PAUSE などの時計操作は対象外で飛ばされること）

## 段階6の動作確認（手動・検証用画面）

1. START 前の通過登録がエラーになること。RUNNING・PAUSE 中はチームごとに登録でき、END 後はエラーになること
2. 他チームの初回通過が 1 周目として数えられ、ラップタイムは「基準なし」になること
3. 「暫定順位」と表示され、周回数 → 同周回の通過時刻の順に並ぶこと。自チームのラップも順位に含まれること
4. 周回数が異なるチーム間では時間差が表示されないこと（周回差のみ）
5. 通過記録の修正・削除・UNDO で順位が更新されること
6. チームを削除しても、そのチームは記録とともに順位に残り「削除済み」と表示されること

## 段階7の動作確認（手動・検証用画面）

1. ラップ登録後、各ラップに車両データ（速度・電圧・電流・積算値）を独立して登録できること
2. 入力値がそのまま表示されること（例：`062.50` が `62.5` にならない）。空欄は「（未入力）」と表示され、0 にならないこと
3. 一部項目の修正で、他の項目が変わらないこと
4. ラップを削除すると車両データ一覧から消え、UNDO（ラップの復元）で元の値のまま再表示されること
5. 車両データの修正を UNDO すると、元の値（未入力を含む）に正確に戻ること

## 段階8の動作確認（手動・検証用画面）

1. 操作者を登録・名前修正・削除できること。削除した操作者が選択肢から消えること
2. 操作者を切り替えても時計が止まらないこと。未設定のままでも記録操作ができること
3. 再起動すると操作者が「未設定」に戻ること
4. メモが日時付きで記録され、改行・カンマ・引用符がそのまま保存されること。空欄・空白のみはエラーになること
5. メモの本文修正で日時が変わらないこと。UNDO で元の本文に戻ること
6. （操作履歴は画面を持たない仕様のため、段階9の CSV で確認します）

## 段階9の動作確認（手動・検証用画面）**― Excel での確認が必要です**

1. 「CSV を出力」→ フォルダを選ぶと、その下に `<大会ID>_<大会名>` フォルダができ、5 ファイルが出力されること
2. **各ファイルを Excel でダブルクリックして開き、日本語が文字化けしないこと**
3. メモの改行・カンマ、チーム名のカンマ・引用符が 1 つのセルに正しく収まること
4. 日時がミリ秒まで日本時間で表示されること（Excel の表示形式によってはミリ秒が隠れるため、セルの値を確認）
5. 車両データの空欄が空欄のまま、`0` は `0` のままであること。`062.50` は Excel が数値として `62.5` と表示する場合があるが、CSV ファイル自体には `062.50` と保存されていること（メモ帳で確認）
6. 同じ大会を再出力すると上書きされ、別大会は別フォルダになること

## 段階10の動作確認（手動・検証用画面）

1. 強制停止時間を登録できること（終了未定も可）。終了日時を後から入力・修正・削除でき、UNDO で戻ること
2. 走行中、各チームの 3・5・10 周平均が表示され、ラップ数が足りない平均は「データ不足（使用数/必要数）」と表示されること
3. 強制停止と重なったラップが「STOPPAGE_OVERLAP」として除外されること（ラップ記録自体は残ること）
4. 今後の強制停止を登録すると S_remaining・R_drive が変わり、予測最終周回数が減ること。重複する停止が二重に数えられないこと
5. 周回数が異なるチーム間の時間差は「推定」と表示され、同周回のときだけ「実測」と表示されること
6. 記録の追加・修正・削除・UNDO、終了予定時刻の変更で予測が更新されること

## 段階11の動作確認（手動・検証用画面）

1. 走行中、条件を満たすと警告一覧に重要度順（重大→注意→情報）で表示されること。音・ポップアップは出ないこと
2. 同じ条件が続く間、同じ警告が重複して増えないこと（発生時刻が変わらないこと）
3. 「確認済み」で一覧から消え、非表示件数が増えること
4. 終了未定の強制停止を登録すると予測に基づく警告の重要度が下がり、停止を削除して重要度が戻ると、確認済みの警告も再表示されること
5. 記録の削除・UNDO で警告が解除・再発生すること（再発生は新しい発生時刻）
6. アプリを再起動すると確認済み状態がリセットされること
7. 開始前・終了後は警告が出ないこと

## 段階12の動作確認（**Windows 実機で確認済み：2026-11-10、ユーザー報告で全項目 OK**）

> 確認した構成：Electron 33.4.11 / better-sqlite3 12.11.1（コミット `1b69f04`）、S モードではない Windows PC。
> 結果：起動（ウィンドウ・React 画面・SQLite・IPC）、スリープ抑止（`powercfg /requests`・消灯/スリープしない・END で解除・電源プラン不変）、
> 終了確認ダイアログ、正常終了／異常終了の判定、復旧確認待ち、サインアウト時の終了、スリープ復帰、CSV（Excel）がすべて OK。
> 未受領：`powercfg /requests` の出力と、スリープ復帰時の「PC実日時 − マスタークロック」「復帰時の時刻ずれ」の数値（単調時計がスリープ中に止まるかの記録用）。
> 未実施として扱うもの：電源ボタン長押しによる強制電源断（項目 8）、ノート PC のフタを閉じたときの動作（項目 10）は、報告に個別の記載がないため、実施したかを確認すること。

1. START 後、**管理者として実行**したコマンドプロンプト（または PowerShell）で `powercfg /requests` を実行し、DISPLAY と SYSTEM に electron.exe（または WGC Race Manager）の要求があること。PAUSE 中も残ること
2. END 後・アプリの正常終了後・タスクマネージャーで強制終了した後に、`powercfg /requests` から要求が消えること
3. 画面の消灯時間・スリープ時間を短く（例：1 分）設定し、走行中は画面が消えずスリープもしないこと。END 後は通常どおり消灯・スリープすること
4. `powercfg /getactivescheme` の結果が、アプリの起動前後で変わらないこと（電源プランを変更しない）
5. 走行中に × ボタン・Alt+F4 で閉じようとすると確認ダイアログが出ること（キャンセルで閉じない、「終了する」で終了）
6. アプリを開いたまま Windows をシャットダウン・ログオフしたとき、確認ダイアログでシャットダウンが止まらないこと（**Electron 33 では事前通知がないため特に重要**。止まった場合は報告）。次回起動時に「前回の終了：正常終了」と表示されること
7. タスクマネージャーで強制終了 → 再起動すると「前回は正常に終了しませんでした」の警告に復旧確認待ちの大会が表示されること。大会を選ぶとレース状態（PAUSED を含む）が戻り、経過時間は停止していた時間も含むこと。電源の抑制が維持されること。確認前は LAP REGISTER・通過登録・PAUSE などがエラーになり、メモは記録できること。「選択中の大会の復旧を確認」の後は通常どおり操作できること（確認しても経過時間・状態は変わらないこと）
7-2. 正常終了 → 再起動では復旧確認待ちにならないこと
8. 電源ボタン長押しで強制的に電源を切る → 再起動しても起動が停止せず（整合性 ok）、確定済みの記録が残っていること
9. スリープ・休止して数分後に復帰し、検証用画面の「PC実日時 − マスタークロック」と「復帰時の時刻ずれ」を確認すること（5 秒を超えて変化した場合は警告が出る。Windows の単調時計がスリープ中に止まるかどうかの確認）
10. ノート PC のフタを閉じたときの動作（アプリでは防げない）と、復帰後の警告
