# 開発環境セットアップ（Windows）

## 必要なもの

- Windows 10 / 11（x64）
- Node.js **22.12 以上**（LTS 推奨）

C++ ビルドツール（Visual Studio Build Tools / Python）は**不要**です。
better-sqlite3 13 は Node-API 対応の Windows x64 用ビルド済みバイナリを同梱しており、Node と Electron の両方で同じバイナリが動作します。

## 初回セットアップ

```powershell
cd wgc-race-manager
npm ci
```

`npm ci` は `package-lock.json` に固定されたバージョンをそのまま入れます（インターネット接続はこの時だけ必要です。アプリ本体はオフラインで動作します）。

## コマンド

| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発モードで起動（ホットリロードあり） |
| `npm run build` | `out/` にビルド |
| `npm start` | ビルド済みのアプリを起動 |
| `npm test` | 自動テスト（Vitest） |
| `npm run typecheck` | 型チェック |

## 段階1の動作確認（手動）

1. `npm run build` → `npm start`
2. 「検証用画面（正式UIではありません）」と表示され、Electron / Node / SQLite のバージョンが表示されること
3. もう一度 `npm start` を実行しても 2 つ目のウィンドウが開かず、既存ウィンドウが前面に出ること（二重起動防止）

## 段階2の動作確認（手動）

1. `npm run build` → `npm start`
2. 検証用画面に `dbPath`（`%APPDATA%\wgc-race-manager\wgc-race-manager.sqlite`）、`dbSchemaVersion` = 1、`dbIntegrity` = ok が表示されること
3. アプリを終了・再起動しても同じ表示になること

## 段階3の動作確認（手動・検証用画面）

1. 大会を作成する（終了予定を開始予定より前にするとエラーになること）
2. 大会を選択し、チームを追加する。自チームを2つ登録しようとするとエラーになること
3. チームを削除すると関連記録の件数が表示され、確認後に「削除済み」と表示されること
4. 「復元」で元に戻ること
5. アプリを再起動しても大会・チームが残っていること

※ 検証用画面の日時入力は PC のローカル時刻として扱います（正式 UI の入力方式は未決定）。

## 段階4の動作確認（手動・検証用画面）

1. 大会を選択し START → 経過時間が進むこと
2. PAUSE → 経過時間が止まり、残り時間は減り続けること。RESUME で再開すること
3. 走行中にアプリを終了して再起動 → 大会を選ぶと状態が RUNNING のまま、停止していた時間も含めて経過時間が復元されること（PAUSE 中に終了した場合は PAUSED のまま）
4. **Windows の時刻設定を手動で変更** → 起動中の経過時間・マスタークロックが影響を受けないこと（「PC実日時 − マスタークロック」の値だけが変わる）
5. 時刻を過去に戻した状態でアプリを起動 → 警告ダイアログと画面上の警告が出ること（記録は書き換わらないこと）
6. 実際の開始時刻の修正 → 経過時間が修正後の値で再計算されること。END 後も修正できること
7. END 後は START/PAUSE/RESUME/END がすべてエラーになること

## 段階5の動作確認（手動・検証用画面）

1. START 前の LAP REGISTER がエラーになること。START 後・PAUSE 中は登録でき、ラップタイムに一時停止中の時間が含まれること
2. END 後の LAP REGISTER がエラーになり、過去記録の追加はできること
3. 過去記録を途中に追加すると周回番号・ラップタイムが再計算されること。開始時刻以前・未来・同一日時はエラーになること
4. 通過日時の修正で、前後の記録を飛び越える修正がエラーになること
5. UNDO で直前の記録操作から順に取り消せること（START/PAUSE などの時計操作は対象外で飛ばされること）

## 段階6の動作確認（手動・検証用画面）

1. START 前の通過登録がエラーになること。RUNNING・PAUSE 中はチームごとに登録でき、END 後はエラーになること
2. 他チームの初回通過が 1 周目として数えられ、ラップタイムは「基準なし」になること
3. 「暫定順位」と表示され、周回数 → 同周回の通過時刻の順に並ぶこと。自チームのラップも順位に含まれること
4. 周回数が異なるチーム間では時間差が表示されないこと（周回差のみ）
5. 通過記録の修正・削除・UNDO で順位が更新されること
6. チームを削除しても、そのチームは記録とともに順位に残り「削除済み」と表示されること

## データの保存場所

`%APPDATA%\wgc-race-manager\wgc-race-manager.sqlite`（WAL モードのため `-wal` / `-shm` ファイルが同じフォルダに作られることがあります。アプリ起動中にこれらを削除・移動しないでください）
