## D-002 一時停止中の時計・残り時間（論点 A-2）

- 日付：2026-11-09
- 決定：予定終了時刻は変更せず、一時停止中も残り時間は減り続ける。
  - マスタークロック：常時進行する。
  - 残り時間：予定終了時刻を基準に進行する（PAUSE の影響を受けない）。
  - レース経過時間：PAUSE 中は停止し、RESUME で再開する。
  - 他チームの通過記録：マスタークロックを基準に記録できること（PAUSE 中も記録可能）。
- 補足：
  - アプリ上の一時停止（PAUSE）と、大会全体の公式な競技停止（強制停止時間 §4.5）は**別概念として区別する**。
  - 強制停止時間の戦略計算への反映方法（論点 A-7）は**未確定**。該当段階（段階10）の着手前に確認する。

## D-003 自チームの記録（論点 A-4）

- 日付：2026-11-09
- 決定：
  - 自チーム：自チーム専用のラップ記録（`lap_records`）を使用する。
  - 他チーム：チーム別の通過記録（`competitor_passes`）を使用する。
  - 全チームの順位・戦略計算では、両方の記録を統合して扱う。
  - 全チーム通過記録に自チームを重複登録する必要はない。

## D-004 検証用画面（論点 B-1）

- 日付：2026-11-09
- 決定：検証用画面を設置してよい。
- 条件：

  - 正式な画面構成・レイアウト・配色・操作性はユーザーが後から決定する。
  - **検証用画面のデザインを正式 UI の仕様として扱わない。**

## D-005 周回番号・ラップタイムの保存（論点 A-6）

- 日付：2026-11-09
- 決定：
  - DB には通過日時のみを保存し、周回番号・ラップタイムは通過日時から算出する（保存しない）。
  - CSV には算出した周回番号・ラップタイムも出力する。
  - 自チームの初回ラップはレース開始日時を基準とする。
  - **他チームの初回ラップは、基準時刻が確定するまで算出しない**（§20「他チームの初回通過時刻の基準」が未確定のため）。

## D-006 車両データの保存形式（論点 A-9）

- 日付：2026-11-09
- 決定：
  - 速度・電圧・電流・積算値の **4 項目すべてを入力された文字列のまま保存**する（数値変換しない）。
  - 空欄は未入力として扱う（0 にしない）。
  - 積算値の意味・単位は推測しない。

## D-007 チーム削除時の記録（論点 A-13）

- 日付：2026-11-09
- 決定：論理削除を採用する。
  - 削除前に関連記録の件数を確認する。
  - 削除済みチームの過去記録は保持する。
  - 記録が存在するチームのデータを物理削除しない。
  - 誤削除時に復元できる構造にする。
  - **削除済みという理由だけで、過去の競技記録や CSV 出力から除外しない。**
- 優先事項：レース中の誤操作で、過去の通過記録や順位計算に必要なデータが失われないこと。
- 補足：「チームの削除」と「競技上の順位計算」の分離設計は [design/team-deletion.md](./design/team-deletion.md)（D-008〜D-010 で承認）。

## D-008 削除済みチームの各機能での扱い

- 日付：2026-11-09
- 決定：チームの削除は **新規入力の対象から外す操作** としてのみ扱う。
  - 新しい通過登録：削除済みチームは受け付けない。
  - 順位・周回差・戦略予測：削除済みチームも含める。
  - 通常 CSV：削除済みチームの記録も出力する。
  - CSV には削除済みであることを示す列を追加する（列名・形式は段階9で確認）。

## D-009 削除済みチームの過去記録

- 日付：2026-11-09
- 決定：
  - 削除済みチームの過去記録の **修正・追加ともに許可** する（誤削除後でも競技記録を正確に保つことを優先）。
  - 修正・追加は通常どおり操作履歴に記録する。
  - 修正・追加を行ってもチームの削除済み状態は維持する（自動で復元しない）。
  - 必要に応じてチームを復元できるようにする。

## D-010 順位対象外（失格・リタイア等）の仕組み

- 日付：2026-11-09
- 決定：
  - 競技上の順位対象外にする仕組みは、**チームの削除とは完全に分離** する。
  - 正式な大会規則の確認後に別途仕様を決定する。**現段階では推測で実装しない。**

## D-011 START / PAUSE / RESUME / END とラップ計測の連動（論点 A-5）

- 日付：2026-11-09
- 決定：レース時計と自チームのラップ計測を連動させる。
  - START：レース経過時間の開始。自チーム初回ラップの基準時刻（実際の開始時刻）を確定する。
  - LAP REGISTER：自チームの通過日時を記録する（段階5で実装）。
  - PAUSE：レース経過時間を一時停止する。
  - RESUME：レース経過時間を再開する。
  - END：レースを終了する。
- ラップタイムは実際の通過日時の差から算出する。**一時停止中の時間もラップタイムに含める。**
- PAUSE 中もマスタークロックと他チームの通過記録は動作させる（D-002 と整合）。

## D-012 実際の開始時刻の修正

- 日付：2026-11-09
- 決定：
  - 実際の開始時刻は後から修正できる。**レース終了後も修正可能。**
  - 変更前・変更後の日時を操作履歴に保存する。
  - 修正後は自チームの初回ラップタイムを再計算する（周回番号・ラップタイムは保存せず算出するため、D-005 により自動的に反映される）。

## D-013 PC の時刻異常

- 日付：2026-11-09
- 決定：
  - 起動時、前回保存した日時より PC の時刻が過去になっていた場合は警告を出す。
  - **自動補正は行わず、保存済みの日時情報を書き換えない。**
  - 時系列に異常が発生したことを識別できるようにする。

## D-014 強制停止時間の実装時期

- 日付：2026-11-09
- 決定：
  - 強制停止時間の登録・変更機能は **段階10** で実装する（段階4では実装しない）。
  - 段階4では時計の基本機能を優先する。ただし、後から強制停止時間を戦略計算に組み込める設計にする。

## D-015 日時の保持（論点 A-3 の一部）

- 日付：2026-11-09
- 決定：
  - 現段階ではマスタークロックの日時と PC の実日時の **両方を保持** する。
  - 内部保存は UTC ミリ秒、表示は日本時間とする。
  - CSV にどちらを出力するかは **段階9** で決定する。

## D-016 LAP REGISTER を受け付ける状態

- 日付：2026-11-09
- 決定：
  - PREPARING（START 前）：拒否
  - RUNNING：受け付ける
  - PAUSED：受け付ける（マスタークロックは進行しているため通過日時を記録できる）
  - FINISHED：その場での登録は拒否。END 後の追加・修正は過去記録の操作機能から行う
- ラップタイムは実際の通過日時の差から算出し、一時停止中の時間も含める（D-011 と同じ）。

## D-017 UNDO（直前操作の取り消し）の範囲（論点 A-11）

- 日付：2026-11-09
- 決定：
  - 対象：大会内のすべての記録操作
    - 自チームのラップ記録
    - 他チームの通過記録
    - 車両データ
    - メモ
    - チーム情報の追加・編集・削除・復元
  - 複数段階の UNDO に対応する。**REDO は実装しない。**
  - UNDO 自体も操作履歴に記録する。
  - 操作者が切り替わっても UNDO できる（操作者ごとではなく大会単位）。
  - **対象外**：レース時計の状態遷移（START / PAUSE / RESUME / END）。
  - 後続の変更があるデータを古い状態に無条件で戻さない。**整合性を確認してから** UNDO する。

## D-018 過去記録の日時範囲

- 日付：2026-11-09
- 決定：
  - 実際の開始時刻より前の日時：拒否
  - 同じチームの同一日時の通過記録：拒否（ラップタイム 0 の発生を防ぐ）
  - 異なるチームの同一日時の通過記録：許可
  - 時系列の整合性が崩れる修正：拒否

## D-019 END の扱い

- 日付：2026-11-09
- 決定：現行仕様（§12）を維持する。END は取り消し不可とし、終了後の時計再開や END の UNDO は実装しない。

## D-020 他チームの周回数の数え方（§20「他チームの初回通過時刻の基準」の一部）

- 日付：2026-11-09
- 決定：
  - 通過回数 = 周回数とし、初回通過を 1 周として数える。
  - レース開始時点のスタートライン通過は登録しない運用とする（アプリで自動判定はしない）。
  - 初回通過のラップタイムは基準時刻がないため算出しない（D-005 と同じ）。

## D-021 他チーム通過を受け付ける状態

- 日付：2026-11-09
- 決定：
  - START 前：拒否
  - RUNNING・PAUSED：受け付ける
  - FINISHED：その場での通過登録は拒否し、過去記録の追加で対応する
- 運用：最終通過は通過登録してから END する。

## D-022 他チーム過去記録の日時範囲

- 日付：2026-11-09
- 決定：自チームの D-018 と同じ規則を適用する。
  - 実際の開始時刻以前、現在より未来、同一チームの同一日時は拒否する。
  - 修正によって時系列（周回の順序）が破綻する場合は拒否する。
  - 異なるチーム同士の同時刻は許可する。

## D-023 暫定順位の計算（§8.3）

- 日付：2026-11-09
- 決定：
  - §8.3 の暫定ルールを段階6で実装する。周回数が多いチームを上位とし、同周回数ならその周回の通過時刻が早いチームを上位とする。
  - 画面上では「暫定順位」と明示する。
  - 正式な大会規則が判明した際に、順位計算ロジックを差し替えられる構造にする。

## D-024 UNDO の制限の見直し（段階5で導入した制限について）

- 日付：2026-11-09
- 決定：
  - 車両データが付いたラップ・記録が紐づいたチームの「追加」を取り消せない制限は、現時点では安全側の措置として許容する。
  - 理想は「後続の操作を先に UNDO すれば、元の追加操作も取り消せる」こと。段階7・8で車両データとメモの入力機能を実装する際に、UNDO の制限を改めて見直す。
