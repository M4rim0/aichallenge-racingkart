# 設計：警告判定（段階11）

> 状態：**実装済み**。関連決定：D-056〜D-062、D-069（暫定解釈 W-1〜W-11 を正式化。W-2・W-10 は変更）
> 実装：`src/shared/warnings/detect.ts`（判定、純粋関数）、`src/main/services/warning-service.ts`（状態管理）、
> `src/shared/warnings/types.ts`（表示用の型）

## 構成

```
StrategyService.buildInput ──► computeStrategy（段階10） ──► detectWarnings（純粋関数）──► WarningService（状態）──► IPC ──► 画面
                    │                                            ▲
                    └──── 指紋（現在時刻を除く元データ）──── 前回の予測順位（メモリ）
```

- **判定（detect.ts）**：戦略計算の結果だけを入力に、その時点で成立している警告を返す。DB・Electron・時刻に依存しない。
- **状態管理（WarningService）**：発生・継続・解除・重要度上昇・確認済みをメモリ上で管理。DB には何も保存しない（スキーマ変更なし）。再起動で全てリセット。
- **通知・表示**：現在は画面の一覧のみ（音・ポップアップなし）。将来の音・通知は、`evaluate` の結果のうち `phase = 'NEW'` の警告を通知部に渡す形で追加できる。
- 警告は記録ではないため、操作履歴・UNDO の対象外。記録の追加・修正・削除・UNDO・強制停止・終了予定の変更は、次の評価で自動的に反映される。

## 警告の種類（D-057）

| 種別（type） | キー | 情報 | 注意 | 重大 |
|---|---|---|---|---|
| ① 後方チームの急接近 `REAR_APPROACH` | `REAR_APPROACH:<後方チームID>` | 10 周平均のみ / 3 周平均のみ（W-1） / 追いつく可能性（W-3） | 5 周平均を含む / 時間差 2 分以内（W-2：後方の全チーム） | 3 シナリオすべて / 時間差 1 分以内 |
| ② 前方チームを追い抜ける可能性 `FRONT_OVERTAKE` | `FRONT_OVERTAKE:<前方チームID>` | 1 シナリオ | 2 シナリオ | 3 シナリオ |
| ③ 自チームのペース変化 `OWN_PACE` | `OWN_PACE:<ID>:SLOWER` / `:FASTER` | 悪化 5% 以上 / 改善 5% 以上（W-4） | 悪化 10% 以上 | 悪化 15% 以上 |
| ④ 順位予測の大幅変化 `PREDICTED_RANK_CHANGE` | `PREDICTED_RANK_CHANGE:<自チームID>` | 1 位 | 2 位 | 3 位以上 |
| ⑤ 他チームの急激なペース変化 `TEAM_PACE` | `TEAM_PACE:<ID>:SLOWER` / `:FASTER` | 5% 以上 | 10% 以上 | 15% 以上 |

- 境界値は「以上」「以内」を含む（浮動小数点の誤差は 1e-9 の許容差で吸収）。
- ①の種類（`kind`）：`OVERTAKE`（予測順位が入れ替わる＝追い抜かれる）、`CATCH_UP`（同じ周回に並ばれるが順位は維持＝追いつかれる）、`PROXIMITY`（予測ではなく現在の時間差が近い）。時間差は後方の全チームについて計算する（W-2、D-069）：同周回はその周回の通過時刻の差（実測）、異周回は「推定走行位置の差 × そのチームの 5 周平均ペース」（推定）。最終通過時刻の単純差は使わない。後方にいるだけでは警告せず、時間差が 2 分以内（注意以上）・1 分以内（重大）の場合に限る。境界判定には 1 マイクロ秒未満の許容差を設ける（推定値の計算誤差の吸収）。重要度は「予測による重要度」と「時間差による重要度」の高い方。
- ③⑤のペース変化は 3 周平均と 10 周平均の比較（段階10の `pace.change`）。方向が変わると別の警告（別キー）。
- ④の「前回計算時」（W-5）：元データ（記録・強制停止・終了予定・状態など、現在時刻を除く）が変わった最初の計算で「今回」を確定し、それまでの「今回」を「前回」とする。画面の定期更新（時間の経過）だけでは前回値を更新しない。比較は自チーム・5 周平均シナリオ。メモリ上のみ。

## 不確実性への対応（D-058、W-6〜W-9）

| 状況 | 対応 |
|---|---|
| データ不足 | 平均・予測がないため該当する判定を行わない（警告は出ない） |
| 記録が古い（OVERDUE） | ①②：当事者どちらかが OVERDUE のシナリオは数えない。①の時間差・③⑤：5 周平均シナリオで OVERDUE なら使わない／出さない |
| 強制停止中 | ③⑤（ペース警告）を出さない |
| 終了未定の停止あり | 残り走行可能時間に依存する警告（①の予測部分・②・④）を 1 段階下げる。情報は情報のまま。①の時間差による下限は下げない |
| 終了予定時刻未設定 | 予測がないため②④と①の予測部分は出ない（①の時間差による接近は出る） |
| 時刻異常（TIMELINE_ANOMALY） | 重大を注意に制限 |
| 開始前・終了後 | 警告を出さない（W-8） |

抑制した判定は `suppressed` として理由付きで返す（参考情報。警告ではない）。

## 状態管理（D-059, D-060）

| 出来事 | 動作 |
|---|---|
| 条件が成立（キーが新しい） | 新しい警告（新しい `occurrenceId`）。発生から 10 秒間は `phase = NEW`（W-10） |
| 条件が継続 | 同じ警告を維持（`occurrenceId`・発生時刻は同じ）。発生（または重要度上昇）から 10 秒を過ぎたら `phase = CONTINUING`。内容・重要度の低下は反映し、確認済みは維持 |
| 重要度が上昇 | 同じ警告を更新、`escalatedAt` を記録、そこから 10 秒間 `phase = NEW`、**確認済みを解除して再表示** |
| 条件が解消 | 警告を解除（確認済みかどうかに関係なく） |
| 「記録が古い」ことだけで判定が抑制された（D-074） | **解除しない**。`occurrenceId`・確認済み・重要度を維持し、新しい記録が入った後の通常の判定に任せる（記録が古い間に新しく発生させたり重要度を上げたりはしない） |
| 再び成立 | 新しい警告（新しい `occurrenceId`）として表示 |
| 確認済みにする | 一覧から非表示（`acknowledgedCount` に数える）。解消とは独立 |
| 古い `occurrenceId` で確認済み | 拒否（既に解除・再発生している） |
| アプリ再起動 | すべてリセット（DB に保存しないため） |

表示順：重要度（重大→注意→情報）→ 新規 → 種別 → 現在順位。

## IPC

- `warnings:evaluate(eventId)` → `WarningList`（評価して状態を更新し、確認済みを除いた一覧を返す）
- `warnings:acknowledge(eventId, occurrenceId)`

## 「新規」の期間（W-10、D-069）

発生（または重要度上昇）から 10 秒間（マスタークロック基準、ちょうど 10 秒で「継続中」）。
