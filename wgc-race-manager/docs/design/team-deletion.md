# 設計提案：チームの削除と競技上の順位計算の分離

> 状態：**承認済み**（D-008〜D-010、2026-11-09）。
> 順位計算・入力制限・CSV 上の扱いは該当段階（3 / 5 / 6 / 9 / 10）で実装する。
> 関連決定：D-003, D-005, D-007, D-008, D-009, D-010

## 1. 問題

決定 D-007 により「削除済みという理由だけで過去の競技記録や CSV 出力から除外しない」。
一方で、ユーザーがチームを「削除」する理由は複数ありうる。

| 削除の理由（例） | 本来の意味 | 順位計算に含めるべきか |
|---|---|---|
| 登録ミス（存在しないチームを登録した） | 登録の取り消し | 記録が無ければ影響なし。記録があれば要判断 |
| レース中の誤操作で削除してしまった | 誤削除 | **含めるべき**（復元までの間も順位を壊さない） |
| リタイア・失格 | 競技上の扱いの変更 | 大会規則による（未確定） |

「削除」という 1 つのフラグで「入力対象から外す」と「順位から外す」の両方を表すと、
誤削除の瞬間に順位・周回差・予測が変わってしまい、レース中の判断を誤らせる。

## 2. 提案：2 つの軸を分離する

### 軸1：登録状態（`teams.deleted_at`）― 段階2で実装済み

- 意味：**入力・選択の対象から外す**だけ。
- 削除済みチームの通過記録・ラップ記録・車両データはそのまま保持され、復元（`deleted_at` を NULL に戻す）で元通りになる。
- 削除・復元はどちらも操作履歴に記録する（復元は「編集」として記録）。

### 軸2：競技上の扱い ― **未実装・未確定**

- 意味：順位計算に含めるか（例：失格・リタイア等で順位対象外にする）。
- 大会規則（§20「正式な同周回順位判定ルール」と同様）に依存するため、**推測で列や状態を追加しない**。
- 必要と判断された場合に、`teams` とは別の列またはテーブルとして追加する（マイグレーションで後付け可能）。

### 各機能での扱い（提案）

| 機能 | 削除済みチームの扱い（提案） |
|---|---|
| 新規の通過登録（段階6） | 受け付けない（入力対象外のため）。復元すれば再び登録可能 |
| 過去記録の修正・追加・削除 | 受け付ける。操作履歴に記録し、チームの削除済み状態は維持する（D-009） |
| 現在順位・周回差（段階10） | **含める**（軸2 で明示的に除外されない限り） |
| 戦略予測・警告（段階10/11） | 含める |
| 通常の記録 CSV（段階9） | **出力する**。チームが削除済みであることを示す列を付ける案（列名・形式は段階9で確認） |
| 操作履歴 CSV | 削除・復元の操作を出力する |
| 自チーム | 自チームを削除すると「自チーム不在」となる。自チームの削除は特に誤操作の影響が大きいため、追加の確認を行うかは UI 確定時に判断（B-4） |

## 3. 記録そのものの削除との違い

| | 記録の論理削除（`lap_records.deleted_at` 等） | チームの論理削除（`teams.deleted_at`） |
|---|---|---|
| 意味 | その記録は誤りだった | そのチームを入力対象から外す |
| 順位計算 | 除外する | 除外しない（上表） |
| 通常 CSV | 除外する（仕様 §13） | 除外しない（D-007） |
| 操作履歴 | 残る | 残る |

## 4. 段階2で実装済みの保護

- **物理削除の禁止**：全テーブルに `BEFORE DELETE` トリガーを設定し、SQL の `DELETE` を DB レベルで拒否する。アプリのバグや誤操作でも行は消えない。
- **操作履歴の改ざん禁止**：`operation_history` と `race_clock_transitions` は追記のみ（UPDATE も拒否）。
- **大会をまたいだ混在の禁止**：通過記録・ラップ記録の `team_id` が別大会のチームを指す場合はトリガーで拒否。
- **自チームの一意性**：削除されていない自チームは 1 大会に 1 つまで（部分一意インデックス）。
  自チームが既にある状態で、削除済みの旧自チームを復元しようとするとエラーになる（データは変更されない）。
- **関連記録件数の取得**：`TeamRepository.countRelatedRecords()` で、有効なラップ記録・通過記録・車両データの件数を返す。

## 5. 決定結果

1. 「各機能での扱い」は上表のとおり（D-008）。
2. 削除済みチームの過去記録の修正・追加を許可（D-009）。
3. 軸2（競技上の扱い）は大会規則の確認後に別途決める。推測で実装しない（D-010）。
